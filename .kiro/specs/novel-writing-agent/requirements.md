# Requirements Document

## Introduction

本功能旨在构建一个完整的 AI 小说创作工作台（Novel Writing Agent）。系统提供网页版用户界面，支持作者以项目为单位组织小说内容，包括章节、人物设定、世界观与大纲等结构化数据，并提供对话式的写作、续写、改写与润色能力。

系统采用前后端分离架构：前端使用 React + TypeScript 实现交互界面；后端使用 Node.js（Express 或 Fastify）+ TypeScript 提供数据持久化与模型代理服务。所有小说数据与模型凭据保存在服务端，支持用户跨设备访问同一份数据。

模型接入采用统一的 OpenAI 兼容接口：用户在设置中配置 base URL、API Key 与模型名称，后端作为代理将请求转发到任意兼容提供商，实现多模型接入。

## Glossary

- **系统（System）**：整个 AI 小说创作工作台，包含前端应用与后端服务。
- **前端（Frontend）**：基于 React + TypeScript 的网页用户界面。
- **后端（Backend）**：基于 Node.js + TypeScript 的服务端，负责数据持久化、模型代理与业务逻辑。
- **项目（Project）**：一部小说的顶层容器，聚合该小说的章节、人物、世界观与大纲等内容。
- **章节（Chapter）**：项目下的可编辑文本单元，包含标题、正文与排序位置。
- **人物（Character）**：项目下描述角色设定的结构化条目，包含姓名、描述等字段。
- **世界观（WorldSetting）**：项目下描述背景设定的结构化条目，包含标题与内容。
- **大纲（Outline）**：项目下描述故事结构的结构化条目，包含标题、内容与排序位置。
- **模型配置（ModelConfig）**：用户提供的模型接入参数，包含 base URL、API Key 与模型名称。
- **模型代理（ModelProxy）**：后端组件，使用模型配置将写作请求转发到 OpenAI 兼容的提供商接口。
- **写作请求（WritingRequest）**：用户在编辑器中发起的写作、续写、改写或润色操作请求。
- **对话会话（ChatSession）**：用户与模型代理之间围绕某章节进行的对话式交互上下文。
- **数据存储（DataStore）**：后端用于持久化项目、章节、人物、世界观、大纲与模型配置的存储机制。

## Requirements

### 需求 1：项目管理

**用户故事：** 作为作者，我希望以项目为单位创建和管理我的小说，以便将不同小说的内容彼此隔离并集中组织。

#### 验收标准

1. WHEN 用户提交包含项目名称的创建请求，THE 后端 SHALL 在数据存储中创建一个新项目并返回该项目的唯一标识符。
2. WHEN 用户请求项目列表，THE 后端 SHALL 返回数据存储中所有已保存项目的名称与唯一标识符。
3. WHEN 用户提交针对某项目标识符的删除请求，THE 后端 SHALL 从数据存储中删除该项目及其关联的章节、人物、世界观与大纲。
4. WHEN 用户提交针对某项目标识符的重命名请求，THE 后端 SHALL 在数据存储中将该项目名称更新为请求中提供的名称。
5. IF 创建项目的请求中项目名称为空字符串，THEN THE 后端 SHALL 拒绝该请求并返回校验错误信息。
6. IF 用户请求的项目标识符在数据存储中不存在，THEN THE 后端 SHALL 返回资源不存在错误信息。

### 需求 2：章节管理与编辑

**用户故事：** 作为作者，我希望在项目中创建、编辑和排序章节，以便撰写并组织小说正文。

#### 验收标准

1. WHEN 用户在某项目下提交包含章节标题的创建请求，THE 后端 SHALL 在数据存储中为该项目创建一个新章节并返回该章节的唯一标识符。
2. WHEN 用户请求某项目的章节列表，THE 后端 SHALL 按章节排序位置升序返回该项目的全部章节标题与唯一标识符。
3. WHEN 用户提交针对某章节标识符的正文更新请求，THE 后端 SHALL 将该章节的正文内容更新为请求中提供的内容并持久化到数据存储。
4. WHEN 用户提交针对某章节标识符的删除请求，THE 后端 SHALL 从数据存储中删除该章节。
5. WHEN 用户提交针对某项目的章节排序请求，THE 后端 SHALL 按请求中提供的章节标识符顺序更新各章节的排序位置。
6. IF 用户请求的章节标识符在数据存储中不存在，THEN THE 后端 SHALL 返回资源不存在错误信息。

### 需求 3：结构化设定管理（人物、世界观、大纲）

**用户故事：** 作为作者，我希望管理人物设定、世界观与大纲，以便维护小说的结构化背景信息。

#### 验收标准

1. WHEN 用户在某项目下提交人物条目的创建请求，THE 后端 SHALL 在数据存储中为该项目创建包含姓名与描述的人物条目。
2. WHEN 用户在某项目下提交世界观条目的创建请求，THE 后端 SHALL 在数据存储中为该项目创建包含标题与内容的世界观条目。
3. WHEN 用户在某项目下提交大纲条目的创建请求，THE 后端 SHALL 在数据存储中为该项目创建包含标题与内容的大纲条目。
4. WHEN 用户请求某项目的人物、世界观或大纲列表，THE 后端 SHALL 返回该项目对应类型的全部条目。
5. WHEN 用户提交针对某人物、世界观或大纲条目标识符的更新请求，THE 后端 SHALL 将该条目的字段更新为请求中提供的值并持久化到数据存储。
6. WHEN 用户提交针对某人物、世界观或大纲条目标识符的删除请求，THE 后端 SHALL 从数据存储中删除该条目。
7. IF 用户请求的条目标识符在数据存储中不存在，THEN THE 后端 SHALL 返回资源不存在错误信息。

### 需求 4：模型配置管理

**用户故事：** 作为作者，我希望配置模型接入参数，以便系统能够调用我选择的 AI 提供商进行写作。

#### 验收标准

1. WHEN 用户在设置中提交包含 base URL、API Key 与模型名称的模型配置，THE 后端 SHALL 将该模型配置持久化到数据存储。
2. WHEN 用户请求查看已保存的模型配置，THE 后端 SHALL 返回 base URL 与模型名称，并以掩码形式返回 API Key。
3. WHEN 用户提交模型配置的更新请求，THE 后端 SHALL 将数据存储中的模型配置更新为请求中提供的值。
4. IF 用户提交的模型配置中 base URL 为空字符串、API Key 为空字符串或模型名称为空字符串，THEN THE 后端 SHALL 拒绝该请求并返回校验错误信息。
5. WHERE 用户已保存模型配置，THE 后端 SHALL 在处理写作请求时使用该模型配置。

### 需求 5：模型代理转发

**用户故事：** 作为作者，我希望后端代理我的写作请求到所配置的提供商，以便统一接入任意 OpenAI 兼容的模型而无需在前端暴露 API Key。

#### 验收标准

1. WHEN 后端接收到写作请求，THE 模型代理 SHALL 使用已保存的模型配置向对应 OpenAI 兼容接口发起补全调用。
2. WHEN 模型代理收到提供商返回的成功响应，THE 后端 SHALL 将生成的文本内容返回给前端。
3. WHILE 模型代理正在以流式方式接收提供商的响应，THE 后端 SHALL 将已接收的文本增量逐段转发给前端。
4. IF 用户尚未保存模型配置时发起写作请求，THEN THE 后端 SHALL 返回提示用户先配置模型的错误信息。
5. IF 提供商接口返回错误状态或请求超时，THEN THE 后端 SHALL 向前端返回包含失败原因的错误信息。
6. THE 后端 SHALL 在转发请求时将 API Key 仅置于服务端到提供商的请求中，不在返回给前端的响应中包含 API Key。

### 需求 6：对话式写作能力

**用户故事：** 作为作者，我希望通过对话方式对章节进行写作、续写、改写与润色，以便在创作过程中获得 AI 协助。

#### 验收标准

1. WHEN 用户针对某章节提交续写请求，THE 后端 SHALL 将该章节的现有正文作为上下文连同用户指令发送给模型代理。
2. WHEN 用户针对选定文本提交改写或润色请求，THE 后端 SHALL 将选定文本连同改写或润色指令发送给模型代理。
3. WHEN 模型代理返回生成结果，THE 前端 SHALL 在对话会话中展示生成的文本内容。
4. WHEN 用户在对话会话中确认采用某段生成文本，THE 前端 SHALL 将该文本插入或替换到章节编辑器的目标位置。
5. WHERE 项目中存在人物、世界观或大纲条目，THE 后端 SHALL 支持将用户选定的设定条目内容附加到写作请求的上下文中。
6. THE 后端 SHALL 在同一对话会话内保留先前的用户指令与模型响应作为后续写作请求的上下文。

### 需求 7：数据持久化与多设备访问

**用户故事：** 作为作者，我希望我的小说数据保存在服务端，以便从不同设备访问同一份内容。

#### 验收标准

1. WHEN 后端创建或更新项目、章节、人物、世界观、大纲或模型配置，THE 后端 SHALL 将变更写入数据存储。
2. WHEN 前端在任意设备发起数据读取请求，THE 后端 SHALL 从数据存储返回最新已持久化的内容。
3. WHILE 后端服务重启后再次启动，THE 后端 SHALL 从数据存储恢复此前已持久化的全部项目数据。
4. IF 数据存储在读写操作中返回失败，THEN THE 后端 SHALL 向前端返回包含失败原因的错误信息。

### 需求 8：前端工作台界面

**用户故事：** 作为作者，我希望通过网页界面访问所有功能，以便在浏览器中完成小说创作。

#### 验收标准

1. WHEN 用户打开网页应用，THE 前端 SHALL 展示项目列表并提供创建新项目的入口。
2. WHEN 用户选择某个项目，THE 前端 SHALL 展示该项目的章节列表、人物、世界观与大纲。
3. WHEN 用户选择某个章节，THE 前端 SHALL 在编辑器中展示该章节的正文内容供编辑。
4. WHEN 用户编辑章节正文并触发保存，THE 前端 SHALL 向后端提交正文更新请求。
5. THE 前端 SHALL 提供设置界面用于查看与更新模型配置。
6. IF 后端返回错误信息，THEN THE 前端 SHALL 向用户展示该错误信息。
