# Requirements Document

## Introduction

本功能为现有的 AI 小说创作工作台（Novel Writing Agent）新增「章节蓝图与分场景写作模块」（Chapter Blueprint Module）。目标是让写作 Agent 从「直接写一章」升级为「先规划再写作」：根据用户给出的章节大纲、目标字数、剧情要求与节奏要求，自动拆分章节结构、分配场景字数、按场景写作、检查字数与节奏，并支持局部扩写与重写。

本模块是对既有系统的扩展，必须沿用现有的 TypeScript 全栈技术栈：前端 React + TypeScript，后端 Node.js + Fastify + TypeScript，持久化使用既有的文件型数据存储（DataStore），模型调用复用既有的模型代理（ModelProxy，OpenAI 兼容流式转发）与模型配置（ModelConfig）。本模块与既有的项目（Project）、章节（Chapter）、人物（Character）、世界观（WorldSetting）、大纲（Outline）数据模型集成；合并后的整章正文写入既有 Chapter 的正文字段。

核心流程：用户给出章节需求 → 系统生成结构化章节蓝图（JSON）→ 按场景写正文 → 合并整章 → 字数与节奏检查 → 局部扩写或重写。

实现按阶段推进（用于后续任务划分）：

- **阶段一（最小可用）**：蓝图生成、分场景写作、章节合并、整章生成（需求 1–8、13–15）。
- **阶段二（可控写作）**：字数检查、局部扩写、局部重写（需求 9、11、12）。
- **阶段三（质量检查）**：节奏检查与质量报告（需求 10）。

## Glossary

- **系统（System）**：扩展后的整个 AI 小说创作工作台，含前端应用与后端服务。
- **前端（Frontend）**：基于 React + TypeScript 的网页用户界面。
- **后端（Backend）**：基于 Node.js + Fastify + TypeScript 的服务端，负责业务逻辑、数据持久化与模型代理转发。
- **数据存储（DataStore）**：后端用于持久化项目、章节、人物、世界观、大纲、模型配置以及本模块新增数据的存储机制。
- **模型代理（ModelProxy）**：既有后端组件，使用模型配置将请求转发到 OpenAI 兼容的提供商接口并流式产出文本。
- **模型配置（ModelConfig）**：既有的模型接入参数，包含 base URL、API Key 与模型名称。
- **项目（Project）**：一部小说的顶层容器，聚合章节、人物、世界观与大纲等内容。
- **章节（Chapter）**：项目下的可编辑文本单元，包含标题、正文与排序位置。
- **章节蓝图（ChapterBlueprint）**：描述某一章节施工方案的结构化数据，包含章节级字段与场景数组，以 JSON 形式持久化。
- **场景（Scene）**：章节蓝图中的最小施工单元，包含目标字数、地点、出场角色、目的、情绪、节奏、必含要点与结束状态。
- **场景正文（SceneDraft）**：针对单个场景生成的正文文本，关联到对应章节蓝图与场景标识符。
- **蓝图生成器（BlueprintGenerator）**：后端组件，读取项目设定并调用模型代理生成章节蓝图。
- **蓝图解析器（BlueprintParser）**：后端组件，将模型返回的文本解析为章节蓝图对象。
- **蓝图序列化器（BlueprintSerializer）**：后端组件，将章节蓝图对象序列化为 JSON 文本。
- **场景写作器（SceneWriter）**：后端组件，根据单个场景的蓝图约束生成场景正文。
- **整章生成器（ChapterWriter）**：后端组件，按场景顺序生成全部场景正文并触发合并。
- **章节合并器（ChapterMerger）**：后端组件，按场景顺序拼接场景正文为完整章节正文。
- **字数检查器（WordCountChecker）**：后端组件，统计场景与整章实际字数并与目标字数对比生成报告。
- **节奏检查器（PacingChecker）**：后端组件，依据蓝图节奏要求检查章节正文生成报告。
- **场景扩写器（SceneExpander）**：后端组件，对指定场景按指定字数扩写。
- **场景重写器（SceneRewriter）**：后端组件，根据修改要求重写指定场景。
- **实际字数（ActualWordCount）**：一段正文去除所有空白字符后剩余字符的数量。
- **目标字数（TargetWords）**：用户或蓝图为章节或场景设定的期望字数，取正整数。
- **字数检查报告（WordCountReport）**：场景与整章实际字数、与目标字数差距及扩写建议的结构化结果。
- **节奏检查报告（PacingReport）**：依据蓝图节奏要求得出的剧情点完成情况、禁止事项违反情况、问题与修改建议的结构化结果。

## Requirements

### 需求 1：章节需求输入

**用户故事：** 作为作者，我希望以标准模板或一句话简化形式提交章节需求并指定目标字数，以便灵活地驱动章节蓝图生成。

#### 验收标准

1. THE 后端 SHALL 要求生成章节蓝图的请求包含目标章节标识符、目标字数与章节需求文本。
2. THE 蓝图生成器 SHALL 接受标准模板格式与单句简化格式两种章节需求文本作为生成输入。
3. IF 生成章节蓝图请求中的目标字数不是 100 至 100000 之间的正整数，THEN THE 后端 SHALL 拒绝该请求并返回校验错误信息。
4. IF 生成章节蓝图请求中的章节需求文本为空字符串或长度超过 5000 个字符，THEN THE 后端 SHALL 拒绝该请求并返回校验错误信息。
5. IF 生成章节蓝图请求缺少目标章节标识符、目标字数或章节需求文本中的任一项，THEN THE 后端 SHALL 拒绝该请求并返回校验错误信息。

### 需求 2：章节蓝图生成

**用户故事：** 作为作者，我希望系统读取项目设定并生成结构化章节蓝图，以便写作按规划进行而不跑偏。

#### 验收标准

1. WHEN 用户提交生成章节蓝图的请求，THE 蓝图生成器 SHALL 从数据存储读取该项目的大纲、人物与世界观条目作为生成上下文；当某一类条目不存在时，以空集合作为该类上下文。
2. WHEN 蓝图生成器完成生成上下文组装，THE 蓝图生成器 SHALL 通过模型代理请求生成结构化章节蓝图。
3. THE 章节蓝图 SHALL 包含 chapter_id、title、target_words、main_goal、tone、pacing、required_plot_points、forbidden_points、emotional_curve、scenes 与 ending_hook 字段。
4. THE 章节蓝图中的每个场景 SHALL 包含 scene_id、name、target_words、location、characters、purpose、emotion、pacing、must_include 与 ending_state 字段。
5. IF 用户在发起生成章节蓝图请求时尚未保存模型配置，THEN THE 后端 SHALL 返回提示用户先配置模型的错误信息，并不向模型代理发起调用。
6. IF 模型代理在生成章节蓝图时返回错误或超时，THEN THE 后端 SHALL 返回包含失败原因的错误信息。

### 需求 3：章节蓝图解析与序列化

**用户故事：** 作为作者，我希望生成的章节蓝图被可靠地解析与存储，以便后续写作与检查基于一致的结构化数据运行。

#### 验收标准

1. WHEN 模型代理返回含有章节蓝图 JSON 的文本（可能夹带额外说明文字），THE 蓝图解析器 SHALL 从该文本中提取 JSON 片段并解析为章节蓝图对象。
2. THE 蓝图序列化器 SHALL 将章节蓝图对象序列化为 JSON 文本。
3. WHEN 一个合法章节蓝图对象被序列化为 JSON 文本后再次解析，THE 蓝图模块 SHALL 产出一个所有章节级与场景级字段值与原对象逐一相等的章节蓝图对象。
4. IF 模型代理返回的文本中不存在可提取的合法 JSON 片段，THEN THE 蓝图解析器 SHALL 返回描述解析失败原因的错误信息。
5. IF 解析得到的对象缺少需求 2 所列的章节级字段或场景级字段，THEN THE 蓝图解析器 SHALL 返回描述缺失字段的错误信息。

### 需求 4：章节蓝图结构校验

**用户故事：** 作为作者，我希望章节蓝图满足结构规则，以便场景拆分与字数预算保持合理。

#### 验收标准

1. THE 蓝图模块 SHALL 以「所有场景 target_words 之和与章节 target_words 之差的绝对值除以章节 target_words」计算偏差比例。
2. IF 解析得到的章节蓝图的场景数量小于 3 或大于 7，THEN THE 蓝图生成器 SHALL 返回提示场景数量超出允许范围的校验错误信息。
3. IF 所有场景 target_words 之和与章节 target_words 的偏差比例严格大于 0.1，THEN THE 蓝图生成器 SHALL 返回提示场景字数分配不合理的校验错误信息。
4. IF 同一章节蓝图中存在重复的 scene_id，THEN THE 蓝图生成器 SHALL 返回提示场景标识符重复的校验错误信息。
5. IF 章节蓝图的章节 target_words 或任一场景 target_words 不是正整数，THEN THE 蓝图生成器 SHALL 返回提示字数取值非法的校验错误信息。

### 需求 5：章节蓝图持久化

**用户故事：** 作为作者，我希望章节蓝图被持久化并关联到项目与章节，以便跨会话与跨设备继续工作。

#### 验收标准

1. WHEN 蓝图生成器生成并通过校验的章节蓝图就绪，THE 后端 SHALL 将该章节蓝图持久化到数据存储并关联到对应项目与章节。
2. WHEN 用户请求某章节的章节蓝图，THE 后端 SHALL 从数据存储返回该章节最新已持久化的章节蓝图。
3. WHEN 用户针对已存在章节蓝图的章节再次生成蓝图，THE 后端 SHALL 用新蓝图替换数据存储中该章节的既有蓝图，并仅保留一份蓝图。
4. IF 用户请求的章节标识符在数据存储中不存在，THEN THE 后端 SHALL 返回资源不存在错误信息。
5. IF 数据存储在读写章节蓝图时返回失败，THEN THE 后端 SHALL 返回包含失败原因的错误信息。
6. IF 用户请求的章节存在但在数据存储中尚无已持久化的章节蓝图，THEN THE 后端 SHALL 返回资源不存在错误信息。

### 需求 6：分场景写作

**用户故事：** 作为作者，我希望系统依据蓝图逐个场景写正文，以便获得可控的、分场景的草稿。

#### 验收标准

1. WHEN 用户针对某章节蓝图中的单个场景提交写作请求，THE 场景写作器 SHALL 读取该场景的 target_words、purpose、must_include 与 ending_state 作为写作约束。
2. WHEN 场景写作器组装写作上下文，THE 场景写作器 SHALL 将该场景所列出场角色的人物设定纳入写作上下文。
3. WHERE 目标场景在蓝图顺序中存在上一场景且该上一场景已有已持久化的场景正文，THE 场景写作器 SHALL 将上一场景的正文纳入写作上下文。
4. WHEN 场景写作器完成上下文组装，THE 场景写作器 SHALL 通过模型代理以流式方式生成该场景正文。
5. WHEN 场景正文生成完成，THE 后端 SHALL 将该场景正文持久化到数据存储并关联到对应章节蓝图与场景标识符。
6. IF 用户请求的场景标识符在该章节蓝图中不存在，THEN THE 后端 SHALL 返回资源不存在错误信息。
7. IF 用户在发起场景写作请求时尚未保存模型配置，THEN THE 后端 SHALL 返回提示用户先配置模型的错误信息。
8. IF 模型代理在生成场景正文时返回错误或超时，THEN THE 后端 SHALL 返回包含失败原因的错误信息，并不持久化部分生成的场景正文。

### 需求 7：整章生成

**用户故事：** 作为作者，我希望系统按顺序写完所有场景并合并为整章，以便从蓝图一次得到整章初稿。

#### 验收标准

1. WHEN 用户针对某章节蓝图提交整章生成请求，THE 整章生成器 SHALL 按场景 scene_id 升序依次生成每个场景的正文。
2. WHEN 整章生成器完成某场景正文生成，THE 后端 SHALL 在开始生成下一场景之前将该场景正文持久化到数据存储。
3. WHEN 全部场景正文生成完成，THE 整章生成器 SHALL 调用章节合并器将各场景正文合并为完整章节正文。
4. IF 整章生成过程中某场景生成失败，THEN THE 整章生成器 SHALL 停止生成后续场景，THE 后端 SHALL 返回包含失败原因的错误信息并保留此前已持久化的场景正文。
5. IF 用户在发起整章生成请求时尚未保存模型配置，THEN THE 后端 SHALL 返回提示用户先配置模型的错误信息，并不向模型代理发起调用。

### 需求 8：章节合并

**用户故事：** 作为作者，我希望按顺序将场景合并为连贯的整章，以便阅读并保存组装后的章节。

#### 验收标准

1. WHEN 用户针对某章节蓝图提交合并请求，THE 章节合并器 SHALL 读取该章节蓝图全部已持久化的场景正文。
2. THE 章节合并器 SHALL 按场景 scene_id 升序拼接各场景正文为完整章节正文。
3. WHEN 章节合并器完成合并，THE 后端 SHALL 将合并后的章节正文写入数据存储中对应章节的正文字段。
4. IF 章节蓝图中存在尚无已持久化场景正文的场景，THEN THE 章节合并器 SHALL 返回提示存在未写作场景的错误信息，并不修改数据存储中对应章节的正文字段。
5. IF 用户请求合并的章节在数据存储中尚无已持久化的章节蓝图，THEN THE 后端 SHALL 返回资源不存在错误信息。

### 需求 9：字数检查

**用户故事：** 作为作者，我希望按场景与整章对比目标字数与实际字数，以便定位需要扩写的位置。

#### 验收标准

1. WHEN 用户针对某章节提交字数检查请求，THE 字数检查器 SHALL 统计每个场景正文的实际字数与整章正文的实际字数；对尚无已持久化正文的场景，其实际字数计为 0。
2. THE 字数检查器 SHALL 计算每个场景实际字数与其蓝图 target_words 的差值，以及整章实际字数与章节 target_words 的差值。
3. WHERE 某场景的「不足比例」（即（target_words − 实际字数）÷ target_words）达到或超过 0.15，THE 字数检查器 SHALL 在字数检查报告中为该场景生成扩写建议，并给出等于（target_words − 实际字数）的建议扩写字数。
4. WHEN 字数检查完成，THE 后端 SHALL 将字数检查报告持久化到数据存储并关联到对应章节。

### 需求 10：节奏检查

**用户故事：** 作为作者，我希望系统依据蓝图检查节奏，以便情绪曲线、必含剧情点与禁止事项得到遵守。

#### 验收标准

1. WHEN 用户针对某章节提交节奏检查请求，THE 节奏检查器 SHALL 依据该章节蓝图的 pacing、emotional_curve、required_plot_points 与 forbidden_points 检查章节正文。
2. THE 节奏检查报告 SHALL 为每个 required_plot_points 标注完成状态为已完成、部分完成或未完成之一。
3. WHERE 章节正文出现违反某条 forbidden_points 的内容，THE 节奏检查器 SHALL 在节奏检查报告中标注被违反的禁止事项。
4. THE 节奏检查报告 SHALL 按场景给出节奏问题、修改建议与取值为高、中或低之一的修改优先级。
5. WHEN 节奏检查完成，THE 后端 SHALL 将节奏检查报告持久化到数据存储并关联到对应章节。
6. IF 用户在发起节奏检查请求时尚未保存模型配置，THEN THE 后端 SHALL 返回提示用户先配置模型的错误信息，并不向模型代理发起调用。

### 需求 11：局部扩写

**用户故事：** 作为作者，我希望按指定字数扩写指定场景而不改变剧情走向，以便在不重写整章的情况下补足字数。

#### 验收标准

1. WHEN 用户针对某场景提交扩写请求，THE 后端 SHALL 要求该请求包含目标章节标识符、目标场景标识符与表示期望新增字数的扩写字数。
2. IF 扩写请求中的扩写字数不是 1 至 100000 之间的正整数，THEN THE 后端 SHALL 拒绝该请求并返回校验错误信息。
3. WHEN 场景扩写器处理扩写请求，THE 场景扩写器 SHALL 读取该场景当前正文与蓝图约束，并通过模型代理生成扩写后的场景正文。
4. THE 场景扩写器 SHALL 在扩写指令中要求保留该场景既有关键剧情、维持原有剧情走向、避免新增重大设定，并要求扩写后场景正文的实际字数达到该场景当前正文实际字数与扩写字数之和。
5. WHEN 场景扩写器完成扩写，THE 后端 SHALL 仅将扩写后的正文写入数据存储中目标场景的正文字段，并保持该章节其他场景的正文不变。
6. IF 用户请求的场景标识符在该章节蓝图中不存在，THEN THE 后端 SHALL 返回资源不存在错误信息。
7. IF 用户请求的目标场景在数据存储中尚无已持久化的场景正文，THEN THE 后端 SHALL 返回提示该场景尚未写作的错误信息。
8. IF 用户在发起扩写请求时尚未保存模型配置，THEN THE 后端 SHALL 返回提示用户先配置模型的错误信息。

### 需求 12：局部重写

**用户故事：** 作为作者，我希望根据修改要求重写指定场景并保留其剧情功能，以便局部修改而不破坏整章结构。

#### 验收标准

1. WHEN 用户针对某场景提交重写请求并提供修改要求，THE 场景重写器 SHALL 读取该场景当前正文、蓝图约束与用户修改要求作为重写上下文，并通过模型代理生成重写后的场景正文。
2. THE 场景重写器 SHALL 在重写指令中要求保留该场景在蓝图中承担的剧情功能（purpose 与 must_include）并维持与相邻场景的衔接。
3. WHEN 场景重写器完成重写，THE 后端 SHALL 仅将重写后的正文写入数据存储中目标场景的正文字段，并保持该章节其他场景的正文不变。
4. IF 用户请求的场景标识符在该章节蓝图中不存在，THEN THE 后端 SHALL 返回资源不存在错误信息。
5. IF 重写请求中的修改要求文本为空字符串，THEN THE 后端 SHALL 拒绝该请求并返回校验错误信息。
6. IF 用户请求的目标场景在数据存储中尚无已持久化的场景正文，THEN THE 后端 SHALL 返回提示该场景尚未写作的错误信息。

### 需求 13：数据持久化与恢复

**用户故事：** 作为作者，我希望章节蓝图、场景正文与检查报告保存在服务端，以便跨设备访问并在服务重启后恢复。

#### 验收标准

1. WHEN 后端创建或更新章节蓝图、场景正文、字数检查报告或节奏检查报告，THE 后端 SHALL 将该变更写入数据存储。
2. WHEN 后端服务重启后再次启动，THE 后端 SHALL 从数据存储恢复此前已持久化的章节蓝图、场景正文与检查报告，且恢复后的数据与服务重启前最后一次持久化的数据一致。
3. WHEN 用户请求某章节的字数检查报告或节奏检查报告，THE 后端 SHALL 从数据存储返回该章节最新已持久化的对应报告。
4. WHEN 用户删除某章节或该章节所属项目，THE 后端 SHALL 删除该章节关联的章节蓝图、场景正文与检查报告。
5. IF 用户请求的章节在数据存储中尚无已持久化的字数检查报告或节奏检查报告，THEN THE 后端 SHALL 返回资源不存在错误信息。
6. IF 数据存储在写入或读取章节蓝图、场景正文或检查报告时返回失败，THEN THE 后端 SHALL 返回包含失败原因的错误信息。
