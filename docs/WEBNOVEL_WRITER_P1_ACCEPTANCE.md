# Webnovel Writer 接入：P1 写前任务书与提交校验

日期：2026-09-15。范围：小说、短剧的确定性写前任务书、来源版本校验与界面。基于 P0 PR #71、#72；由用户合并，不包含生产部署。

## 行为契约

- 任务书顺序为本次目标、时间边界、必须承接、禁项、作者约束、来源摘录。每条指令引用资料标识，模型输入与界面使用同一份冻结任务书。
- 来源覆盖项目资料集合，能够识别新增、删除人物或世界资料；不能只检查生成开始时已存在的记录。此前正文按目标章集筛选，后续正文不进入历史事实。大纲属于剧情安排，不能据此认定后续事件已经发生。
- 任务书不新增模型调用。参考摘录每项最多 500 字符、合计最多 6000 字符；强制要求不因摘录预算被截断。这是任务书参考区预算，不是整个模型上下文的总预算，也不是历史检索。
- 正文版本与来源版本分别校验。前者保护当前编辑，后者保护人物、大纲、前章、作者约束等依赖。内容 hash 绑定实际候选，旧报告不能用于批准后来修改过的正文。
- 页面区分“下次写前依据”预览和实际生成使用的依据；资料失效时显示过期。没有任务书的历史正文不伪造生成记录。旧服务端没有相应接口时隐藏面板。

## 小说入口

对话写作在正文增量之前通过 `write_brief` SSE 事件传递冻结任务书，前端单独消费，不把 JSON 拼入正文。生成前保存当前编辑并冻结目标、选择范围与编辑版本；采用时先预览最终正文，再通过专用生成内容入口提交。

| 接口 | 用途 |
| --- | --- |
| `GET /api/chapters/:chapterId/write-brief` | 当前预览或已生成正文的实际依据与有效性 |
| `POST /api/chapters/:chapterId/generated-content` | 接受作者确认的完整正文与原始 `writeBrief` |

提交入口由服务端计算最终正文 hash，并在 FileDataStore 修改状态之前同步核对来源与目标 revision。不能先异步检查，再使用普通手工保存绕过校验。普通手工编辑继续使用原入口，同时清除失效的生成标记。该接口接受作者预览确认后的完整正文，不使用客户端签名证明每个字都来自模型。

蓝图、场景生成、扩写、重写、断点续写、整章合并和 Agent 直接写作均使用同一套来源规则。场景正文单独绑定自身及前一场景的输入内容，合并校验参与合并的草稿版本。已有草稿没有可靠来源时保留供作者查看，重新生成后才能自动复用。

场景依赖随草稿持久化并递归检查；重写前场会使相关后续草稿失效，合并正文也保留实际场景依赖。已有生成蓝图先校验原始依据，不能在资料变化后通过新建任务书重新标为有效。历史章写作和审查按实际章节顺序屏蔽未来正文及无法按时点追溯的全局记忆；完整历史记忆查询仍属于 P2。

前端刷新后可以查看原预览，但缺少本次编辑会话上下文的旧预览需要重新生成才能采用；不允许借普通手工保存自动采用旧模型候选。

本阶段拒绝不支持来源校验的 `USE_PYTHON_CORE=1` 写作分支；默认 TypeScript 路径继续可用。未引入新的 Python 运行时。

## 短剧入口

`GET /api/script/projects/:projectId/episodes/:episodeNumber/write-brief` 返回本集预览或实际生成依据。直接正文与结构化正文路径均使用任务书，并通过已有 checkpoint、上游引用及候选 hash 绑定生成与审查。

提交继续使用原有正文与连续性原子提交；在该边界检查任务书与来源集合。手写正文不要求伪造模型任务书。历史连续性回看限定到目标集之前，不从今天的全局状态倒灌未来事实。

## 验证与边界

本阶段离线验证使用真实文件存储和模拟提供商；不使用用户 Key，不修改生产数据。`WritingBriefAcceptance.test.ts` 串联实际生成服务、SSE、采用接口与 FileDataStore，覆盖正常采用与重启、重复采用、人物修改/新增/删除、错目标及非法任务书，拒绝时比较存档文件字节保持不变。

最终全量：后端 125 个测试文件、1065 项测试通过；前端 35 个测试文件、337 项测试通过，合计 1402 项。前后端 typecheck 与生产构建通过。子代理交付后进行了主代理串联验收及独立交叉 review，发现的场景依赖、旧蓝图重新绑定和报告来源问题已修复并回归。

任务书面板另经本地 Edge 无头浏览器检查桌面和 390 像素窄屏：当前/过期状态、逐条来源与展开摘录可见，无水平溢出或页面错误；这是组件实机渲染验证，不代表生产页面已部署。

100 集真实文件离线夹具保持 320 次模型桩调用，完成后重复运行不再调用模型。独立检出的 P0 基线同一测试耗时 5.32 秒；P1 测得 22.27 秒，项目文件约 6.55 MB、累计检查点约 27.62 MB。增加来源快照有实际序列化和存储开销；这些数字是本机离线夹具结果，不能当作线上模型生成延迟。本阶段仅将该整书测试超时设为 60 秒，其余测试保留原超时。

仍属后续阶段：来源事实的时间区间、作者纠错管理、正式接受与同步意图的持久化事务、重放恢复、历史检索及伏笔界面。P1 的来源校验不能替代 P2 的可恢复同步，也不证明模型输出的语义、文笔或长期连续性已全部正确。真实 10 集短剧、20 章小说验收需另行记录明确的模型配置与预算。
