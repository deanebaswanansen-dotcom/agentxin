# Webnovel Writer 接入：小说来源、作者工作台与历史检索

日期：2026-09-15。基于 PR #74 的短剧来源契约，补齐小说接受记录、两个模式的记忆工作台、作者纠错、伏笔管理和关键词检索。继续独立实现机制，没有移植上游代码、提示词、夹具或插件。本次交付由用户合并，不执行生产部署。

## 功能与操作

小说普通保存仍然保留草稿。作者在“故事记忆”里查看保存版完整正文，明确确认后才接受为记忆来源；确认绑定 revision 和全文 hash，另一窗口改过正文则返回 409，原稿和预览保留。已通过生成流程的候选在原子接受边界落盘，反思提取失败时保留待审候选，恢复时复用正文。

小说正式正文、不可变接受记录和待同步意图保存在同一个文件事务中。小说存储的所有写操作统一使用排队、复制候选、原子落盘、发布内存的顺序，磁盘失败不会先把新状态暴露给读者。手改、改名、删除、重排会撤回受影响来源及依赖它的后文；原正文保留，历史接受记录可审计。同步使用冻结输入，不再调用模型抽取。

小说和短剧共用“来源事实 / 作者纠错与偏好 / 伏笔账本 / 关键词检索”。来源显示章集及保存版本，可打开正文并定位真实引文；只有资源、版本、块和引用匹配时才高亮。小说段落内的 UTF-16 位置转换为编辑器全文位置，重复引文不会靠第一次文本匹配错误定位。

作者记录有集合版本、独立 ID、启用状态、重要性和生效范围。表达偏好可以编辑、停用和删除。事实纠错要求选择真实接受来源并明确确认撤回影响；记录与撤回在同一事务落盘，正文不会被自动改写。删除或停用纠错不自动恢复旧来源。来源被撤回后，裁决继续以作者指示生效，不冒充新的正文证据。并发编辑返回 409，界面保留表单，读取最新记录对照后才允许重试。

伏笔的建议期限、紧迫度、状态和作者指定必达章集共享排序规则。只有启用且在生效范围内的未回收伏笔，恰逢 `requiredAtUnit` 时进入本次硬约束；普通逾期仅提醒。旧来源上的安排不能重新开启后来已回收的伏笔，被撤回或未来来源上的安排不作为当前来源使用。无正文来源的作者伏笔单独标记。

## 写作与恢复边界

确定性任务书消费同一套有效来源、作者记录、伏笔与检索结果。整个记忆段绑定任务书 fingerprint，在实际保存事务内重建来源校验；作者控制变化、上游正文变化或旧候选迟到均不能覆盖新状态。来源摘要、未核实抽取和历史正文观察有明确标记，引用匹配只证明出处，不证明叙事语义。

短剧普通生成、结构化审查和分集大纲不再通过原始连续性快照重复注入完整冻结正文。已有冻结接受历史的失效集不能由旧兼容修复流程自动重新接受；作者重新处理并明确接受后才可继续。真正无冻结接受历史的旧格式恢复仍保留兼容路径。

小说审查前情仅取目标章之前的当前接受来源。旧滚动伏笔、自动诊断和审阅报告继续保留为可查看文档，但不会被自动复制为已发生事实或硬设定；作者显式附带这些报告时标为未核实参考。核心状态门在当前接受来源上重建，旧记忆镜像不决定正式接受是否成功。

两种模式使用同一恢复 runner：启动扫描、持久化租约、失败显式重试、过期执行者失效、删除阻止晚写入。查询在当前冻结来源上回退，缓存不可用时不使用过期索引；工作台读取前后核对来源和作者集合版本，无法取得一致视图则有限重试后返回冲突。

## 接口

| 接口 | 行为 |
| --- | --- |
| `GET /api/chapters/:id/accept-source` | 返回保存版完整正文、标题、revision、hash |
| `POST /api/chapters/:id/accept-source` | 以 `expectedRevision`、`expectedContentHash` 明确接受保存版 |
| `GET /api/projects/:id/story-memory` | 返回当前有效来源、作者记录、伏笔与同步状态 |
| `GET /api/projects/:id/story-memory?beforeUnit=N&q=关键词` | 目标章集之前的历史状态与关键词结果 |
| `POST /api/projects/:id/story-controls` | 新建作者记录，携带 `expectedRevision`、`control` |
| `PUT /api/projects/:id/story-controls/:controlId` | 版本化编辑或启停 |
| `DELETE /api/projects/:id/story-controls/:controlId` | 以 `expectedRevision` 删除记录 |
| `GET /api/projects/:id/memory-sync` | 两种模式的独立同步状态 |
| `POST /api/projects/:id/memory-sync/retry` | 只重试派生同步，不需要模型配置 |

沿用请求客户端库隔离，不接受 body 指定其他客户端。具体单库文件实现使用服务端固定范围，客户端作用域代理继续按请求隔离。小说单独部署也注册来源与工作台接口；Netlify 旧兼容函数不因此获得跨实例文件锁或后台短剧存储能力。

## 检索和预算

先过滤客户端、项目、当前接受来源及 `beforeUnit`，再进行中文分词、双字组合和确定性加权。检索同时覆盖有效条目与冻结正文。人物 ID、别名、属性和伏笔 ID 作为查找元数据，不能伪造成引文；作者记录单列，不制造接受 ID。当前状态与历史正文观察分开，正常剧情变化按历史有效区间查询，撤回来源在任何时点均不可用。

结果默认 Top-5，可选 1–20 条；返回文字及引文预算默认 6,000，可选 200–20,000 UTF-16 字符；默认扫描上限 400,000。返回实际扫描/输出字符、匹配原因、耗时和预算耗尽标记。写作记忆段另有总预算：小说最多 16,000 字符；短剧 5,500 字符，对应原有上集承接 2,000 与连续性 3,500 的合计。完整必需事实、状态与作者硬要求优先，无法容纳时明确报错；可选资料按确定顺序截取并记录遗漏。历史摘录不在任务书参考区再次重复注入。

记忆段报告实际字符及按每 2 字符估算的 token，估算不代表供应商计费 usage。正文、世界观、当前大纲等其余 prompt 不包含在该记忆段上限内；原有模型调用与 usage 统计独立保留。同步、作者 CRUD、检索及任务书组装不新增外部模型调用。

固定中文检索评估见 [关键词基线报告](../backend/src/services/retrieval/keyword-evaluation-report.md)：30 个独立查找案例与同一 13 章故事的 20 个跨章案例，覆盖同名人物 ID、别名、远期承诺、道具转交、伏笔关闭、撤回及时间和客户端隔离。46 个正向问题 Top-5 全部命中，2 个应为空的问题均为空，2 个越权请求均被拒绝，错误引文为 0。这些是离线来源召回夹具，不是用户语料效果或真实模型质量证明。可选 Embedding/Rerank 仍按原计划的收益门槛处理：没有用户语料收益与费用对比，不上线，也不在打开项目时发外部索引请求。

## 验收证据与交付状态

主代理在子代理交付后交叉审查并复现修复了：旧来源被兼容修复重新接受、旧报告回灌为事实、未接受草稿进入审查、重复记忆突破预算、首集接受导致任务书误判过期、混合旧格式伏笔关闭后仍被要求承接。恢复用例覆盖实际文件失败、迟到 ACK、客户端隔离、删除、重排和反思失败后正文复用。

浏览器使用隔离临时库、实际 Fastify 后端、Edge headless 与当前前端，禁止模型调用。11 条链路通过：全文预览确认、关键词来源解释、作者偏好、逾期与必达伏笔、390px 抽屉、Esc、短剧工作台、证据跳转高亮、409 保留表单、读取对照后重试、事实纠错撤回而原文不变。浏览器未捕获页面异常。

代码冻结后的后端全量 137 个测试文件、1,213 项通过；前端全量 40 个测试文件、358 项通过，共 1,571 项。两端 typecheck 与生产构建通过，差异空白检查通过。验证命令分别在 `backend`、`frontend` 下执行 `npm test`、`npm run typecheck`、`npm run build`；固定检索矩阵包含在后端全量中。

本次没有使用会话中提供的真实 Key，没有合并、生产部署或修改生产数据。10 集短剧 / 20 章小说的真实模型长流程仍需单独指定模型配置与预算；当前只完成实现与离线验收，不能据此宣称真实创作效果里程碑或百万字稳定性已验证。

新增字段采用向后兼容读取，不伪造旧数据的接受历史；损坏的接受/作者记录读取失败，不静默丢弃。发布前沿用 P2 的成套备份要求。旧版本会丢弃新来源与作者字段，不能直接写回新数据；当前文件队列仅保证一个后端进程，不承诺多进程共享目录的事务安全。
