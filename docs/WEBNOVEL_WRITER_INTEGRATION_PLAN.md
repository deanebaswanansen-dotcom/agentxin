# Webnovel Writer 能力接入计划

状态：计划已整理，功能待实施；本次提交只包含文档。

日期：2026-09-15

适用范围：AgentXin 小说与短剧；短剧先验证，共享能力再接入小说。

本地基线：`main@60b29c59ac7daf60031e291acada1378adc888c4`，已包含 PR #69 的保存冲突、手改连续性和任务恢复修复。线上部署版本需在实施验收时另行核实。

## 1. 接入目标与采用方式

将 Webnovel Writer 的严格产物验收、写前任务书、可追溯记忆、派生数据恢复与历史检索能力，逐步加入现有 React + TypeScript/Fastify 系统。

实施后，作者应能得到以下行为：

1. 接口报错、返回网页、空内容或无效 JSON 时，看到明确原因，原有策划和正文保留。
2. 每章/集生成前，系统明确本次目标、必须承接的事实、禁项及依据；资料修改后旧结果不能冒充新结果提交。
3. 作者能查看当前有效的故事事实、来源章节和纠错记录，并控制纠错是否继续生效。
4. 正文已经保存但摘要、记忆索引同步失败时，能单独补跑同步，无需重新生成正文。
5. 长篇写作能找到较早章节的相关证据，并提醒临近回收时间的伏笔。

采用方式为：参考机制，在现有 TypeScript 后端独立实现。沿用 [短剧稳定性计划](SHORT_DRAMA_RELIABILITY_PLAN.md) 的开源采用边界，不复制 GPL/AGPL 源码；本轮也不移植上游提示词、测试夹具或插件包。来源以固定提交记录，避免把未来分支变化混入本计划。

保留现有 Agent 自主规划、网页操作和 BYOK 配置方式。任务书、验收和提交属于产物边界约束，不把所有创作请求改成不可调整的固定流水线。初期不新增 Python 服务、Claude Code 运行依赖、向量数据库或常驻多 Agent 框架。

### 参考基线

上游：[lingfengQAQ/webnovel-writer](https://github.com/lingfengQAQ/webnovel-writer)，已检查的版本为 v6.2.1 / `master@878ce26e1d544f5c9c7c210b710adf3587ab90d9`。

| 参考机制 | 已核实的实现 | 在 AgentXin 中的采用决策 |
| --- | --- | --- |
| 产物接受边界 | 四份产物做结构校验；审查阻断、履约缺项、实体待消歧会拒绝章节提交 | 候选必须先通过真实内容、领域和版本校验，默认值不能替代创作结果 |
| 写前任务书 | 从章纲与资料生成章节目标、约束和来源记录 | 扩展现有蓝图、分集卡和 checkpoint 元数据 |
| 可追溯记忆 | 事实带来源与状态，旧事实可失效，作者纠错能进入写前上下文 | 扩展现有 MemoryService/Store，并从已有连续性提交投影 |
| 派生数据恢复 | state/index/summary/memory/vector 分别记录同步结果，可重试和重放 | 保留核心原子提交，增加可重建数据的同步记录 |
| 检索与伏笔提醒 | 有关键词/向量混合召回、重排与期限提醒模块 | 先完成关键词检索与可见台账，语义检索作为后续可选增强 |

上游实现的适用边界：部分门禁顺序依赖宿主按提示词执行；提交接受并不等于正文语义被程序证明；检索降级和写作入口的接入并非处处完整；跨文件投影不构成整体事务。本项目应通过实际服务入口、版本绑定和故障测试落实这些边界。Star 数不作为功能验收指标；本次未做上游百万字写作效果验证。

## 3. 必须保持的边界

### 3.1 内容、事实与派生数据

```text
已确认资料 + 当前有效事实 + 作者约束
              ↓
带来源版本的写前任务书
              ↓
模型候选 → 结构/领域/证据引用/版本验收
              ↓
正式正文 + 必需连续性状态 + 派生同步意图
              ↓
摘要 / 记忆查询视图 / 搜索索引（可独立重建）
```

- 短剧继续使用 `commitEpisodeWithContinuity`；正文与下一集必需的连续性状态一起接受，不能拆成两个可能只成功一半的写入。
- `ScriptEpisodeContinuityCommit` 的 `current/stale`、前驱链和 episode revision 仍决定哪些事实可用；不能改成仅凭模型返回 `accepted` 就入库。
- 小说以章节正式资源及其接受记录作为来源。现有 `Chapter.revision` 缺省按 0 兼容读取，但历史缺省版本不能被冒充为已完成来源验证。
- 摘要、搜索索引和通用记忆视图消费接受记录，不反向修改正文或核心连续性。作者显式纠错通过领域操作记录来源，不直接编辑派生快照。
- 历史章/集修改后，相关事实、任务书、审查和索引失效；旧投影任务不得重新激活旧事实。后续章/集沿用现有失效与重新验收路径，不自动重写全文。

### 3.2 状态与成功标准

复用现有 `failed / needs_review / stale / succeeded` 等节点语义。内容验收状态与同步状态是结果的不同维度，不另建一套后台任务状态机。

| 情况 | 用户应看到的结果 | 持久化行为 |
| --- | --- | --- |
| 网页响应、认证/模型错误、空输出、修复后仍不合格 | 生成失败及可执行的修复建议 | 不替换、不自动确认现有创作产物 |
| 需要作者裁决的事实冲突或歧义 | 需要处理，候选可查看 | 保留候选和依据，不记为已接受事实 |
| 生成途中来源被修改 | 资料已变更，候选过期 | 拒绝旧版本提交 |
| 正文与核心连续性已接受，非核心同步失败 | 正文已保存，部分资料待同步 | 保留已接受正文和失败步骤，可重试同步 |
| 关键结果与必需同步均通过 | 已完成 | 下一章/集可以继续使用当前事实 |

可选索引不可用时，可以从当前有效提交直接读取所需事实并明确显示检索降级；无法取得必需事实时暂停后续生成，禁止用过期记忆继续。展示“部分完成”不要求扩展 Job 的终态枚举，可由既有结果携带分项状态。

## 4. 分阶段实施

### P0：修复假成功，建立可信的产物验收

交付：模型连接与策划生成失败可见，原草稿不丢失。这一阶段可单独上线。

- 模型代理验证实际响应协议与内容，覆盖 HTTP 200 HTML、流内错误、空流、只有推理而没有最终内容。对合法但 Content-Type 不规范的服务，以可验证的协议内容判断，避免只靠响应头误拒绝。
- `/api/model-config/test` 没有收到有效最终输出即失败；前端不能把 `receivedOutput: false` 标成测试通过。
- Base URL 提供完整接口路径预览和针对性提示；不对所有服务商盲目补 `/v1`。保留上游状态、错误类别和脱敏原因。
- `ScriptConceptService` 不再把网络、模型或解析失败包装成三个固定“AI 方案”。演示模板如需保留，必须是用户明确选择、带模板来源的独立入口。
- 自动策划输入拆为灵感、项目元数据、已有草稿和明确约束。完整 prompt 与草稿 JSON 不得成为标题、梗概或冲突字段的默认值。
- `{}`、无关对象、缺关键创作内容的结果不能通过补默认值被视为完成。保留现有语法修复、字段别名及非创作性可选默认值；语法可恢复不代表故事内容可以凭空补齐。
- 策划修复次数、备用模型策略沿用已有有限恢复机制；未配置备用模型时不切模型。传输重试、结构修复与任务恢复共享可观察的总尝试预算，避免多层重试次数相乘。失败不自动 approve，不清空旧草稿，不隐藏诊断。
- 已被污染的策划不做后台猜测修复；用户重新生成时保留原内容供核对，只有合格新候选才可替换。

验收：HTML、401/403、模型不存在、429/503、超时、空流、推理-only、错误事件、`{}`、无关 JSON、缺必填内容都显示真实失败；原有策划的内容、状态、revision 保持不变。合法带代码围栏或字段别名的内容仍可恢复；用户手写的有效草稿仍可保存。覆盖“西方玄幻＋项目名称＋当前草稿”复现，页面标题不得出现整份输入上下文。

### P1：带版本和来源的写前任务书

交付：短剧先接入，其后小说接入同一规则；作者能展开查看本章/集的简短依据。

- 从现有策划、已确认大纲/分集卡、人物世界资料、前章/集交接和作者约束生成任务书，优先做确定性组装，不默认增加模型调用。
- 顺序为：本次目标与时间边界 → 必须承接的事实和剧情节点 → 明确禁项 → 当前作者约束 → 相关历史片段与风格参考。
- 扩展已有 `inputRevisionRefs / upstreamArtifactRefs / inputFingerprint / candidateHash`，记录任务书所用资料、连续性提交与作者约束版本；复用现有蓝图和 checkpoint，不创建另一个合同数据库。
- 生成前校验必需资料与来源；提交前在实际服务写入入口重新验证来源和正文版本。审查结论必须绑定当前候选 hash/revision，不能复用旧正文的审查结果。
- 事实冲突与作者修订按当前领域规则处理。主观节奏、爽点、文笔建议仍为 advisory，不因模型评分低就无上限重写。

验收：生成期间修改大纲、人物、前集事实或作者约束，旧候选一律不能覆盖新状态；已完成正文被手改后，旧审查不能批准新正文；直接调用写入 API 与从 UI 操作具有同样的门禁。短剧和小说各有一组承接、禁项与版本冲突夹具。

### P2：可追溯记忆与可恢复同步

交付：先确定共同数据契约和迁移，再分别接入短剧、小说；两个模式完成后才对用户宣布共享记忆能力完成。

拟新增共享来源字段（具体类型随实施 PR 固化）：

| 对象 | 必需信息 |
| --- | --- |
| 来源引用 | 客户端/项目、`chapter` 或 `episode`、资源 ID 与顺序、正文 revision/hash、接受记录 ID、证据位置或短引用 |
| 事实记录 | 稳定 ID、主体与属性、值、来源、有效区间 `[effectiveFromUnit, effectiveUntilUnit)`（结束点可空）、状态 `active/superseded/stale`；剧情时间变化与追溯纠错分开记录 |
| 作者纠错 | 稳定 ID、范围、类别、描述、重要性、启用状态、版本、作者来源；区分表达偏好和对故事事实的修订 |
| 同步记录 | 来源提交 ID/版本、writer 名称与版本、幂等键、尝试次数、`pending/running/succeeded/failed/skipped/stale`、脱敏错误 |

- 扩展现有 `MemoryFact / CriticalStateEntry / Learning / ForeshadowEntry`；短剧事实从当前连续性提交读取，小说事实绑定章节接受记录，向两种模式提供统一查询接口。
- 自动抽取先作为候选；证据必须指向当前版本的正文，未知实体和相互冲突的事实不能被静默补全。补齐真实证据定位，不能将所有新事实统一挂在末尾正文块后便视为已核实。位置与引用验证不能被宣传为已证明全部语义正确。
- 新增按来源 ID/revision 替换、撤回派生记录的入口，不直接调用现有按文本相似度合并并保留较长文案的 `recordFacts()` 完成重放或纠错。查询窗口可继续限量，来源历史及失效依据不应随近期窗口截断而丢失；归档仍须可回溯重建。
- 历史查询按目标章/集的事实生效区间计算状态，不能简单过滤为“今天仍 active”。正常剧情变化只结束旧值的有效区间：第 5 集持有、第 10 集转交的道具，重建第 7 集时仍返回原持有人，第 11 集返回新持有人。追溯纠错则撤回错误来源及其派生版本，不能在历史查询中重新引用被纠错的错误事实；审计历史与创作可用事实分开。`stale` 来源始终不可用，`superseded` 事实在其历史有效区间内仍可用。
- 表达偏好可由作者启用、停用或删除。事实修订走版本化变更及下游失效；与已确认设定冲突时提示裁决，不把一句聊天自动升级为全局事实。
- 正式接受与待同步意图在同一个持久化边界写入。短剧扩展现有原子提交；小说在 `DataStore/FileDataStore` 增加对应的版本化接受边界，MemoryStore 不承担第二次独立“正式接受”。
- 后台同步复用现有执行设施；重启后扫描未完成意图并恢复，不依赖进程内 fire-and-forget。幂等键包含来源提交、writer 与版本；并发重试只保留一个有效执行者。
- 成功接受记录保存重放所需的冻结输入；重放时不能随意读取已变更正文充当旧版本输入。重复执行不重复新增事实，旧版本任务在落盘前再次校验来源。
- 历史变更默认保留来源可审计；用户显式删除纠错、章节或项目时按产品删除语义同步清理派生数据，避免索引把删除内容恢复回来。

验收：在“正式接受前、接受后但调度前、任一 writer 写入中、同步后标记前”注入崩溃，恢复后均不丢正式正文、不重复事实；只重试同步时不发生正文模型调用。两次并发重试、上游修改、旧任务迟到、删除项目均不能复活旧数据。以第 N 章/集生成历史上下文时不得泄漏 N 之后才发生的事实。

### P3：记忆、作者纠错与伏笔界面

交付：接入现有资料面板，用户能查看、纠正和追踪系统实际使用的记忆。

- 提供“当前事实、作者纠错、待回应伏笔、同步状态”入口；显示来源章/集并能跳转证据。内部 JSON、writer 栈信息与原始模型日志不进入正常创作界面。
- 作者可添加、编辑、停用纠错，冲突反馈与保存结果明确；各浏览器继续遵守现有隔离和版本冲突处理。
- 复用现有 `planted/echoed/resolved/dropped` 台账及短剧 thread ID，补结构化回收窗口与可选明确截止章/集。旧的文字窗口无法可靠解析时保留原文并标记待补充，不猜测期限。
- 报告与生成任务书使用同一个伏笔排序函数：先已逾期，再临期，再重要性与时间；已回收和作废项不进入待回应列表。
- 小说和短剧使用各自的章/集单位与节奏规则；不直接套上游固定章节比例。期限默认是提醒，只有作者明确设为本章/集必达要求时才进入对应约束。
- 页面明确区分“正文已保存”“资料同步中/失败”“可以继续”，提供重试相关同步动作。

验收：作者纠错下一次生成可见，停用后不再注入；修改约束会使旧任务书失效。临期、超期、无期限、已回收伏笔的 UI 排序与写前输入一致。删除或修订来源后，记忆面板和生成上下文同时更新，不只刷新其中一处。

### P4：历史检索，先关键词后可选混合检索

交付：先上线无需新增外部服务的历史证据召回；验证收益后再增加可配置语义检索。

- 建立统一检索入口，先检索当前项目有效正文、已接受事实和作者约束；人物 ID/别名、道具、伏笔 ID 可精确命中。中文分词方案通过本项目夹具评估，不照搬单字切分。
- 先按客户端/项目、目标写作进度、来源版本及目标时点的有效区间过滤，再做排序；返回片段、来源与命中原因。未来章/集剧情、草稿、已删除或来源已失效的索引不得进入结果；正常剧情变更前的旧状态按 P2 历史区间规则保留。
- 明确上下文总预算、各区预算与确定性截断规则。初期保持现有小说记忆最多 16,000 字符的上限，短剧遵循现有阶段预算；分别报告实际字符数、估算 token 与供应商实际 usage，不混用单位。关键禁项与承接事实优先；无法在预算内提供必需依据时报告不足。不得把始终为 0 的统计当成预算控制。
- 记录固定样例的关键词检索基线。可选 Embedding/Rerank 通过单独配置与开关启用，默认关闭；密钥沿用请求级 BYOK，不写进索引、任务记录或项目文件。
- 混合检索阶段评估关键词与向量融合、重排的真实收益。Embedding/重排超时或失败时回退到有来源的关键词结果，在用户可理解的位置显示降级；小库与大库路径都必须覆盖。
- 全量建索引和重建前提供范围、预计请求数与成本信息，按用户明确选择执行；优先按内容 hash 增量索引，禁止在打开项目时偷偷批量请求外部服务。

验收：先固定至少 30 条带预期来源的检索样例，覆盖同名角色、别名、跨多章旧承诺、道具转移、伏笔回收；记录 Top-5 证据召回率和零召回比例。跨项目、未来、过期来源命中数为 0；超时与无外部 Key 时关键词检索仍可用。混合检索合并条件为整体召回不低于关键词基线、语义专项确有增益，并提供延迟及调用成本对比；没有增益时保留关键词版本，不为完成清单强行上线。

## 5. PR 拆分、顺序与责任边界

| 顺序 | PR 范围 | 前置依赖 | 可独立验收的交付 |
| --- | --- | --- | --- |
| 1 | P0 模型协议与连接测试 | 已有基线 | 网页/空流不会显示连接成功 |
| 2 | P0 策划失败处理与输入分离 | 1 | 不再出现固定模板冒充生成或 JSON 标题；原草稿保留 |
| 3 | P1 任务书与验收版本绑定 | 2 | 短剧、小说接入点分别验收，写入入口拒绝过期候选 |
| 4 | P2 共享记忆契约、迁移与短剧同步 | 3 | 原子接受、持久化意图、幂等与失效规则成立 |
| 5 | P2 小说接受记录与同步接入 | 4 | 小说使用相同来源和恢复语义，不把滚动摘要当唯一事实源 |
| 6 | P3 记忆/纠错/伏笔界面 | 4、5 | 作者可查看纠正，任务书实际消费，排序一致 |
| 7 | P4 关键词检索与固定评测 | 4、5、6 | 无外部服务即可检索当前有效历史证据 |
| 8 | P4 可选混合检索 | 7 的评测及成本评估 | 明确收益、配置、降级与增量索引，独立开关 |

规模过大的 PR 按小说/短剧适配或存储/UI 再拆分，但不得把缺失对应后端约束的 UI 提前宣称为可用能力。前后端接口负责人先约定类型与状态，再并行实现；主代理独立复现关键失败和验收子代理交付。继续使用 fork 分支提交 PR，由用户合并；本计划不触发生产部署。

## 6. 迁移、发布与回滚

1. **只读盘点**：统计旧章节、连续性提交、记忆字段与未知来源记录；备份后再启用写迁移。盘点不发模型请求。
2. **增量兼容**：新增版本字段与读取适配，迁移可重复执行并记录进度；旧 API 的可选字段与默认读取行为有明确兼容测试。
3. **历史数据诚实标记**：旧记忆无证据或来源版本的条目标为历史未核实参考，可查看但不能直接升级为硬性事实。保留当前设定与已有正文，以当前可验证资料继续或要求补全，不伪造曾经通过的验收记录。
4. **持久化可恢复**：沿用现有原子落盘与项目队列；派生同步意图与来源一起提交。删除、修改和恢复路径同时处理关联任务与索引。
5. **灰度启用**：先独立测试项目，再少量真实项目；新记忆/UI/检索按项目启用。P0 的错误处理修复不提供回退到假成功的开关。
6. **回滚**：关闭可选检索或新查询视图后仍能读取正式正文及核心连续性。数据库/文件版本迁移必须先验证上一可用版本能否读取与写回；不兼容时停止相关写入并使用验证过的迁移恢复工具或成套备份，禁止用旧程序启动后静默丢弃新字段。回滚演练使用测试数据验证，不能覆盖发布后作者的新内容。

所有索引、缓存与重放入口必须带客户端及项目作用域；迁移、重试、项目删除均需要隔离测试。现有数据存储与部署方式的变更只在对应实施 PR 明确列出，本计划不预先引入数据库迁移。

## 7. 总体验收与完成定义

| 维度 | 必须提供的证据 |
| --- | --- |
| 失败真实性 | P0 错误矩阵全部通过；无效响应不新增正式产物、不自动 approve |
| 版本正确性 | 手改、切项目、旧任务晚返回、前章修改后的陈旧提交均被拒绝或失效 |
| 来源可追溯 | 每条新自动事实可定位到有效来源及版本；作者纠错标明作者来源 |
| 恢复正确性 | 崩溃与并发重试后内容不丢、事实不重复；同步重试不重新生成正文 |
| 检索正确性 | 固定夹具召回、来源有效性与上下文预算有自动化检查；越权/未来泄漏为 0 |
| 创作效果 | 独立测试项目跑通 10 集短剧、20 章小说的创作与回收，并人工抽查指定连续性点；不据此宣称百万字稳定 |
| 成本与耗时 | 报告改造前后相同样例的模型调用数、输入输出用量、检索耗时与失败恢复次数；P0、任务书确定性组装、离线同步不额外发正文生成请求 |
| 交付状态 | 区分本地通过、PR 已提交、用户已合并、已部署、线上已验证 |

每个实现 PR 运行相关回归及受影响端 typecheck/build；跨端阶段和里程碑运行前后端完整测试。上述 10 集/20 章是里程碑验收，不在每次 PR 重复消耗模型额度；先离线夹具，再受控短流程，最后在明确模型配置与预算后开展长流程。未经真实验收不得标记相应阶段完成。

本次计划文档只做路径、链接、差异与范围检查，不运行无关业务测试，不调用真实模型。
