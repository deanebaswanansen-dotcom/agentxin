实现采用现有 TypeScript 服务，不引入上游运行时、提示词或源码。P1 任务书、P2 来源记忆与恢复、P3 界面、P4 检索仍按后续阶段交付。

## 已验收的行为

| 场景 | 结果 |
| --- | --- |
| HTTP 200 网页、错误 JSON、空流、空白正文、只有推理 | 连接或生成失败，显示脱敏原因与 HTTP 状态 |
| 已输出正文后收到 SSE 错误事件 | 整次调用失败，不缓存部分结果 |
| 合法 SSE 使用不规范 Content-Type、网络按任意字节切片 | 有效内容仍按顺序解析 |
| 修改 Key 后测试连接、旧空白缓存 | 连接测试直接请求当前提供商；旧空白缓存重新请求 |
| 模型返回空对象、无关 JSON、缺少核心故事字段 | 不生成固定模板，不替换或确认旧策划 |
| 有效故事带代码围栏、字段别名或非核心缺项 | 使用有限语法修复与本地字段补全 |
| 作者灵感、项目元数据、已有草稿 | 独立输入；模型标题和梗概不得由序列化上下文兜底 |
| 模型请求期间手改、切项目、修改灵感 | 页面保留新编辑及 dirty，旧结果不继续自动委托或确认 |
| 网络重试与结构修复连续发生 | 共享四次实际 HTTP 请求预算，保留最终错误；缓存不计 HTTP 次数 |

关键串联测试是 `ScriptProviderAcceptance.test.ts`：仅替换外部 `fetch`，实际执行代理、短剧适配器、策划服务、Fastify 路由和 FileScriptStore。失败前后比较持久化文件字节，防止各层单测通过却仍出现假成功。

并发回归另覆盖旧会话迟到结果与检查点版本分配；不能只依赖前端不渲染旧结果。

## 调用与状态边界

- 一次结构化生成最多三次逻辑调用：主模型、一次修复、已配置的备用模型；实际 HTTP 尝试合计最多四次。传输错误没有可修复正文时跳过结构修复，未配置备用模型时不切换模型。
- 策划失败记录 `needs_review`、脱敏原因与尝试数；失败不改变现有 plan 的内容、状态和 revision。手写草稿沿用原编辑校验。
- 来源于模型的标题、梗概与核心冲突必须非空且不是网页或输入对象回显。这是结构与最低内容校验，不等于已证明故事质量或逻辑正确。
- 前端不能撤回已经在服务端完成的确认请求；若等待期间有新编辑，保留本地内容与原 revision，通过现有冲突处理再保存。
- 旧的污染策划保留供作者核对，本阶段没有后台猜测清洗。
