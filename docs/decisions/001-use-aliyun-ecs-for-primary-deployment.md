# ADR-001：使用阿里云 ECS 作为主要部署环境

## 状态

Accepted

## 日期

2026-08-12

## 背景

AgentXin 包含多轮计划、长篇正文生成、连续性审校和自动修订。单次任务可能持续数分钟，并通过 SSE 持续返回进度。Netlify Functions 部署曾出现 HTTP 502、Inactivity Timeout、后台任务状态延迟和发布额度限制；Netlify Blobs 也增加了本地文件存储与线上存储之间的适配复杂度。

用户规模为本人和少量受邀使用者，不要求每台电脑部署本地服务，也暂不要求账号系统或数据库。每个浏览器继续使用自己的 API Key，并通过客户端编号隔离项目数据。

## 决策

使用阿里云 ECS 常驻运行 Node.js/Fastify 后端，Nginx 提供静态前端并反向代理 `/api`。所有客户端数据统一存放在 ECS 云盘 `/var/lib/agentxin`，仍按 `x-agentxin-client-id` 隔离；前端构建设置 `VITE_AGENT_BACKGROUND_JOBS=false`。计划/短任务使用 SSE，整本与长篇任务写入服务器 `AgentRunStore` 并由后台执行器运行，浏览器按任务 ID 读取进度和结果。

Nginx 对 Agent 路由关闭代理缓冲，并将读写超时设为 3600 秒。公网仅开放 80/443，后端 3000 端口不对公网开放。

## 备选方案

### 继续使用 Netlify

- 优点：静态前端发布简单，无需维护服务器。
- 缺点：长任务受函数执行模型、后台状态轮询和发布额度约束。
- 结论：保留兼容代码，不作为当前主要生产环境。

### 阿里云函数计算

- 优点：无需维护常驻服务器，可按调用计费。
- 缺点：需要重新适配 Netlify Background Functions、状态存储和长流式连接。
- 结论：当前少量用户规模下迁移成本高于收益。

### 纯前端直连模型

- 优点：无后端部署。
- 缺点：无法可靠集中保存项目、长期记忆、参考资料和多步 Agent 状态，跨域兼容性受模型服务商限制。
- 结论：不满足当前 Agent 和持久化要求。

## 后果

- 长任务由常驻进程处理并持久化状态；浏览器断开不取消任务，服务重启后可从章节/场景检查点恢复。
- 数据集中保存在一台 ECS 云盘，无需数据库，但必须建立独立备份。
- 团队需要维护 systemd、Nginx、安全组、系统更新和日志。
- 当前客户端编号仍绑定浏览器，跨设备同步与账号恢复需要后续单独设计。
- 生产使用真实 API Key 前必须部署 HTTPS 或可信私网访问。
