# Webnovel Writer 接入：P2 来源契约与短剧同步

日期：2026-09-15。范围：共享来源契约、记忆文件迁移、短剧原子接受与可恢复投影。基于 P1 PR #73，由用户合并，不包含生产部署。小说正式接受记录、作者纠错界面及检索属于后续批次；本批不代表 P2 全部完成。

## 行为契约

短剧正文、核心连续性提交和同步意图在同一个项目文件中原子保存。冻结来源复用连续性提交 ID，包含客户端、项目、集号、正文版本、按顺序保存的正文块及内容 hash。同步只读取这些已接受输入，不重新抽取正文、不调用模型。下一集必需的核心连续性仍使用现有原子提交链。

项目仅保留当前一份完整替换投影的同步意图；有效接受链改变时增加意图版本。旧接受输入保留供审计，手改和重新验收会撤销失效来源及其后继影响。旧数据没有冻结来源时不会补造接受记录。

证据引用使用正文块 ID、JavaScript UTF-16 起止位置和原文短引用。定位相符标为 `matched`，仅表示引用确实存在，不证明事实语义正确。只有块 ID、缺少原文引用、引用错位的条目属于未核实参考。

查询 `beforeUnit=N` 仅使用第 N 集之前的当前有效来源。剧情中的正常状态变化保留历史含义：第 5 集 A 持有道具、第 10 集转交 B，写第 7 集时仍返回 A，写第 11 集时返回 B。已撤销来源不进入历史或当前结果。尚未同步时直接从当前冻结接受输入计算，不能把旧投影当作最新事实。

## 恢复与删除

同步状态独立于正文是否已保存：`pending / running / succeeded / failed / stale`。执行前持久化租约，写入投影后核对当前意图和租约再确认成功。投影使用来源版本与 writer 版本构成的幂等键；同一输入重放不增加事实，迟到旧版本不能覆盖新结果。

后台启动扫描持久化待同步意图，并定期恢复 pending 和租约到期的 running。失败记录保留脱敏原因，由显式重试入口补跑。重试不需要模型 Key。关闭服务时停止扫描并等待正在执行的本地写入。

实际投影写入和确认在项目队列保护下进行，手改及删除不能穿过这段写入。删除项目还会在记忆文件留下持久化删除标记，阻止迟到写入复活项目；确认操作不得因文件不存在而创建新项目。

当前文件队列与租约保证限定为单个后端进程。多个进程共享同一数据目录需要额外跨进程锁，不能把此实现当作分布式执行锁。

## 接口

多客户端存储沿用请求的客户端库标识，不接受请求体指定另一个客户端。单库本地模式则使用服务端 FileScriptStore 明确绑定的库标识，浏览器自带标识不会造成假冲突；不能根据任意意图内容切换范围。未注入短剧存储的兼容服务不注册这些接口。

| 接口 | 响应 |
| --- | --- |
| `GET /api/projects/:projectId/memory-sync` | 模式、同步状态、意图版本、尝试次数、接受来源数和脱敏错误 |
| `POST /api/projects/:projectId/memory-sync/retry` | 重试短剧同步后返回状态；不需要模型配置 |
| `GET /api/projects/:projectId/source-memory?beforeUnit=N` | 时点查询，包含 `entries`、`unverifiedReferences`、结果来源及 `memorySync` 状态 |

没有接受输入时明确返回 `legacy_untracked` 和空来源，不生成假接受 ID。当前已接受输入中证据不足的条目列入 `unverifiedReferences`；真正没有来源的旧记忆继续保留在原记忆接口，二者不混用。`origin=accepted_sources` 表示本次从正式接受输入直接计算，`origin=projection` 表示使用版本相符的已同步视图。

本批接入持久化后端的启动和关闭流程。现有 Netlify 兼容函数没有注入短剧存储，本批不为该函数增加后台短剧执行或跨实例文件锁。

## 迁移和回滚

旧记忆保留在原接口，新来源投影使用独立分区。记忆文件外层版本升级为 v2，来源分区 schema 为 v1。读取旧 v1 文件时在内存中增量适配，下一次成功写入才持久化 v2；不扫描生产正文或猜测历史来源。读取失败或文件损坏显式报错，不清空撤回记录继续写。写盘成功后才发布新的内存状态。

启用前应成套备份项目、记忆及检查点目录。旧程序不能可靠保存新增字段和删除标记，因此不能直接用旧版本写回新数据；回滚需停止写入，使用对应备份或经过验证的转换流程。本批不执行生产迁移或生产回滚。

已在隔离临时目录使用 P1 `91d080a` 的真实旧 MemoryStore 演练写回：旧实现会忽略输入版本、改写为 v1，并丢弃删除标记。该结果确认旧程序直接写回不可作为回滚方案；演练没有读取生产文件。

## 验收记录

验收使用真实临时文件存储和离线夹具，覆盖接受前失败、接受后执行前中断、投影写入失败、投影成功但确认失败、重放、并发手改、删除和客户端隔离。主代理的 7 项串联验收覆盖实际 FileScriptStore、MemoryStore 及 buildServer；子代理交付后互相审查存储、来源契约和后台接线，主代理补出的本地单库客户端标识问题已修复，并增加 3 项回归。

最终代码全量：后端 130 个测试文件、1,142 项测试通过；前端 35 个测试文件、337 项测试通过，合计 1,479 项。前后端 typecheck 与生产构建通过。测试不使用用户 Key；没有部署或修改生产数据。

本机 100 集离线夹具本批耗时 25.95 秒；P1 上次记录为 22.27 秒。模型桩调用仍为 320 次，完成后重复执行为 0 次。项目文件 7,270,003 字节，累计检查点 27,622,731 字节；额外对这 100 集冻结来源执行一次实际记忆文件投影耗时 32.60 毫秒，记忆文件 704,255 字节。这是离线文件及模拟生成测量，不代表真实模型响应延迟，也未测多进程部署。来源快照确有存储和序列化成本，本批未放宽测试超时。
