# AgentXin 短剧 Flash 轻量优化计划

状态：实施中
版本：v1.0
创建日期：2026-08-17
适用范围：短剧正文生成、轻量校稿、100 集连续生产
关联文档：`SHORT_DRAMA_MODE_SPEC.md`、`SHORT_DRAMA_RELIABILITY_PLAN.md`

## 1. 计划目的

当前短剧链路已经解决“写不出来、坏候选覆盖正式稿、任务无法恢复”的可靠性问题。下一阶段不再增加新的 Agent 框架、数据库或复杂状态机，而是把现有流程压缩成一条适合 DeepSeek V4 Flash 的生产链：

> **照着已确认的大纲写出可用正文，只阻止明确的结构、人物和剧情错误；字数、对白比例和风格偏差作为可见建议，不因追求精确指标反复调用模型。**

本计划只解决三件事：

1. 把正常五集批次从本次实测的 50 次模型调用压到 16–21 次。
2. 自动发现并修复少量明显的人物、动作、证据和道具连续性错误。
3. 把每集大量宽泛建议压缩为最多 3–5 条真正值得处理的问题。

## 2. 线上基线

2026-08-17 使用 `deepseek-v4-flash-vision-exp` 对《灰烬账本》第 6–10 集进行真实生产测试，结果如下：

| 指标 | 实测结果 |
| --- | --- |
| 批次完成情况 | 5/5 集完成 |
| 批次总字数 | 5,211 字 |
| 单集字数 | 928 / 951 / 1,080 / 1,263 / 989 |
| 平均字数 | 1,042 字/集 |
| 估算对白比例 | 47% / 49% / 49% / 60% / 54% |
| 硬性问题 | 0 |
| 待优化问题 | 46 |
| 模型调用 | 50 次，约 10 次/集 |
| 输出 token | 54,461 |
| 缓存命中率 | 14.6% |
| 完成耗时 | 约 2 分钟 |

### 2.1 已经达到的效果

- Flash 可以快速完成五集，不需要升级为推理模型。
- 单集约 900–1,300 字已经具备可读、可拍的正文体量。
- 对白比例约 47%–60%，虽未精确达到 60%，但符合短剧可用范围。
- 正式稿、检查点、连续性提交和批次恢复能够正常工作。
- 字数和对白比例不再导致任务无限失败。

### 2.2 仍需解决的问题

- 五集调用 50 次，明显高于 `SHORT_DRAMA_MODE_SPEC.md` 中正常路径不超过 3 次/集的目标。
- AI 校稿输出 46 条建议，服装、节奏、钩子、措辞等低优先级内容过多。
- 已完成正文仍存在少量明显错误：
  - 第 7 集笔记本已经收起，随后又被重新发现，动作顺序矛盾；
  - 第 9 集笔记本与扫描件的保管、交接关系不清；
  - 少数场景人物表与实际出现人物不一致；
  - 电话、VO 人物被误认为必须在现场；
  - 个别证据早于大纲规定集数出现；
  - 少数动作和对白重复。
- 当前 UI 只有批次总调用统计，无法直接看到每个节点为什么调用、哪一次是 Fixup、续写或网络重试。

## 3. 优化目标

### 3.1 正常生产指标

| 指标 | 目标 |
| --- | --- |
| 正常单集模型调用 | 3 次：场景计划、正文、轻校 |
| 正常五集模型调用 | 16 次左右：批次细纲 1 次＋5×3 次 |
| 五集常见调用上限 | 不超过 21 次 |
| 异常单集硬上限 | 不超过 6 次 |
| 单集正文体量 | 目标值的 75%–125% 可完成；超出时提示 |
| 1,200 字项目建议范围 | 900–1,500 字 |
| 对白比例 | 目标 ±15 个百分点为正常区间 |
| 单集可见建议 | 最多 5 条，默认只展示 3 条最高价值问题 |
| 自动修订次数 | 最多 1 次 |
| 100 集调度 | 20 个固定五集批次，顺序执行，可暂停恢复 |

### 3.2 质量底线

只有以下问题阻止单集完成：

- JSON/领域结构无法解析；
- 空集、空场、重复或非法场号、块 ID；
- 人物 ID 不存在；
- 普通对白人物未登记在当前场景；
- 明确的说话人串线且能定位到正文块；
- 明确命中禁用事实或提前解锁的证据；
- 同一动作或道具状态在相邻正文块中直接自相矛盾；
- 用户人工创建且仍为 open 的 hard 问题；
- revision、输入指纹或连续性 CAS 冲突。

以下内容不阻止完成：

- 900–1,500 字范围内偏离 1,200 字目标；
- 对白比例 45%–75% 内的波动；
- 钩子不够强、节奏略慢、服装信息不足；
- requiredFacts 使用同义表达、无法确定是否遗漏；
- AI 单方面判断的角色动机或情绪偏差；
- 风格不够精彩但不存在明确剧情错误。

## 4. 目标调用链

### 4.1 正常单集

```text
已确认分集卡
  → 场景计划（1 次）
  → 完整正文（1 次）
  → 本地结构检查（0 次模型）
  → 明显错误轻校（1 次）
  → 本地复检（0 次模型）
  → 原子提交 Episode + continuity
```

正常单集共 3 次模型调用。

### 4.2 短稿处理

```text
正文低于目标 75%
  → 保留安全正文
  → 最多续写 1 次
  → 达到建议范围则继续
  → 仍偏短则以 advisory 完成，不继续循环补字
```

删除“最多四轮连续续写”的常规路径。续写必须是追加场内 blocks，不能重写整集。

### 4.3 明显错误处理

轻校只返回最多 3 个高置信问题及白名单 Patch：

- `speaker_attribution`：说话人明显标错；
- `scene_presence`：普通对白人物与场景人物表冲突；
- `action_order`：拿走后又重新发现、离开后又继续在场等；
- `prop_custody`：证据或道具的持有人、位置前后矛盾；
- `evidence_timing`：证据早于大纲允许集数出现；
- `duplicate_beat`：相邻动作或对白明显重复。

如果存在可定位问题，最多调用一次 Patch 修订；修订后只运行本地复检，不再调用第二轮 AI review。无法安全定位的问题保留为建议，不循环修稿。

## 5. 实施任务

### P0：调用可观察性与基线锁定

目标：先解释 50 次调用来自哪里，再删调用。

内容：

- 为每次模型请求记录脱敏指标：
  - `projectId / jobId / episodeNumber / node / stage`；
  - `primary / fixup / fallback / continuation / patch / networkRetry`；
  - 模型名、耗时、输入/输出 token、缓存命中 token；
  - 成功、结构失败、业务失败或网络失败；
  - 不记录 API Key、Authorization、Prompt 正文或原始输出。
- 将批次指标写入 `batch_report`，公开 API 只返回统计数据。
- 在“任务与检查点”中显示：本批调用、续写、修订、token、耗时。
- 建立《灰烬账本》第 6–10 集基线夹具，固定当前 50 次调用数据。

主要文件：

- `backend/src/services/script/agents/ScriptDirector.ts`
- `backend/src/services/script/agents/ProxyScriptModelAdapter.ts`
- `backend/src/services/agent/jobs/AgentRunStore.ts`
- `frontend/src/components/ScriptWorkspace.tsx`

完成标准：不查服务器日志，仅看任务详情就能说明 50 次调用分别属于哪些节点。

### P1：收紧单集调用预算

目标：正常 3 次/集，短稿或结构错误也不会多层重试相乘。

内容：

- 引入每集统一预算：

```ts
interface ScriptEpisodeCallBudget {
  scenePlan: 1;
  draft: 1;
  structureFixup: 1;
  continuation: 1;
  sanityReview: 1;
  patch: 1;
}
```

- 正常路径不使用 `structureFixup / continuation / patch`。
- 正文达到目标 75% 后不再为了接近 1,200 字调用续写。
- 正文低于 75% 时最多续写一次；续写后仍偏短则完成并提示。
- 同一节点已经消耗 Fixup 后，不再自动触发同模型 fallback；只有用户明确配置备用模型时才使用 fallback。
- 网络 429/5xx 仅由 HTTP 层重试，不能同时触发结构层和 JobRunner 重跑。
- 超出每集预算时进入 `waiting_user`，不得自动从头重跑。

完成标准：五集正常批次不超过 21 次；任一单集任何情况下不超过 6 次。

### P2：Flash Prompt 与缓存优化

目标：让 Flash 第一次就写到可用体量，并提高缓存命中率。

内容：

- 固定、缩短系统 Prompt，把稳定规则放前面、动态资料放末尾。
- 单集正文只输入：
  - 当前分集卡；
  - 已确认场景计划；
  - 本集实际人物的精简卡；
  - 世界硬规则和禁止项；
  - 上一集摘要；
  - 与本集相关的道具、伏笔和时间事件。
- 不重复传完整策划、完整 100 集大纲、全部人物传记和完整历史正文。
- 明确要求“完整写完本集”，但字数使用建议范围，不要求精确到单字。
- 固定字段顺序和 JSON Schema，避免等价 Prompt 破坏 DeepSeek 缓存。
- 对白目标写为“约 45%–65%，以冲突推进”，不要求精确 60%。

完成标准：真实五集缓存命中率由 14.6% 提升到至少 30%；首稿进入 900–1,500 字的比例至少 80%。

### P3：轻量明显错误校稿

目标：解决影响拍摄的明显错误，不让 AI 评价文学水平。

内容：

- 将现有宽泛 AI review 改为 `ScriptSanityReview`。
- Prompt 明确禁止输出服装建议、节奏建议、表演建议和泛化钩子建议。
- 每集最多返回 3 个问题；没有明显错误必须返回空数组。
- 每个问题必须包含：
  - `code`；
  - `sceneId`；
  - 可选 `blockId`；
  - 一句话证据；
  - 可选白名单 Patch。
- 高置信 Patch 只允许：
  - 改正 speaker/characterId；
  - 更新场景人物表；
  - 删除相邻重复块；
  - 调整同场内明显乱序的块；
  - 修正道具持有人或删除提前出现的证据块。
- Patch 后运行本地结构、人物、禁项、连续性检查；不再调用 AI 复检。
- VO/OS 人物允许不在物理场景人物表，但其 characterId 必须存在，避免把电话人物误判为现场人物。

完成标准：《灰烬账本》第 7 集重复发现笔记本、第 9 集证据保管矛盾能被发现；合法 VO 不误报为人物未在场。

### P4：建议去重和产品展示

目标：从每批 46 条噪声，收敛为用户能真正处理的问题。

内容：

- 同一集同一 `code + sceneId + blockId` 只保留一条。
- AI 建议与确定性规则命中同一问题时，只显示规则问题。
- 单集默认显示最高优先级 3 条，其余折叠。
- “待校稿”状态只表示存在未处理建议，不等于生成失败。
- 增加筛选：明显错误、连续性、风格建议、已处理。
- 字数与对白比例以数据卡展示，不重复生成人工语言建议。

完成标准：正常单集可见问题不超过 5 条；不存在错误时允许显示“未发现明显问题”。

### P5：100 集顺序生产

目标：在现有五集批次上增加轻量整本执行，不重写调度架构。

内容：

- 保留 1–5、6–10……96–100 的固定批次。
- 新增“连续生成后续批次”开关：
  - 启动前显示预计批次数、调用上限和费用提示；
  - 必须由用户明确确认；
  - 每完成五集持久化后才启动下一批；
  - `waiting_user / failed / cancelled` 立即停止；
  - 页面关闭或服务器重启后从当前批次检查点恢复；
  - 不允许两个重叠批次并行。
- 默认仍为手动逐批；自动连续生成是显式选项。

完成标准：离线 100 集调度测试覆盖 20 个批次、集号 1–100 唯一连续、无重复任务；线上先只跑 10–20 集验证后再放开整本。

### P6：配置项补齐

内容：

- 策划编辑页增加对白比例输入，范围 20%–90%，默认 60%。
- 增加三档轻量预设：
  - 快速样稿：600–800 字；
  - 标准短剧：900–1,200 字；
  - 长集：1,200–1,500 字；
- 预设只填写参数，不改变底层领域模型；始终保留自定义。
- 已有正文后修改字数或对白目标时，明确提示“仅对新生成或重生成集数生效”。

## 6. 测试方案

### 6.1 离线回归

至少新增以下用例：

1. 1,200 字目标，首稿 1,050 字、对白 50%，直接进入轻校，不续写。
2. 首稿 700 字，最多续写一次；续写后无论 880 或 1,050 字都停止补字。
3. 字数 1,350、对白 70% 可以完成，只显示指标，不生成两条文字建议。
4. 普通对白人物不在场景人物表时阻止完成。
5. 合法电话/VO 人物不在现场人物表时允许完成。
6. “拿起笔记本并装袋 → 再次拉开抽屉发现同一本笔记本”被识别为 `action_order`。
7. 道具从许知微持有直接变成顾砚持有、无交接动作时识别为 `prop_custody`。
8. 第 11 集才允许出现的证据在第 7 集出现时识别为 `evidence_timing`。
9. 同一问题被规则和 AI 同时发现时只保存一条。
10. AI 返回服装、节奏、文学性建议时 decoder 丢弃这些类别。
11. 五集正常路径调用不超过 16 次；带一次短稿续写和一次 Patch 时不超过 18 次。
12. 单集结构持续失败时总调用不超过 6 次并进入 `waiting_user`。
13. 100 集按 20 个固定批次顺序完成，失败后不自动跨批继续。
14. 任一轻校或 Patch 失败时正式 Episode 与 continuity 不改变。

### 6.2 真实 Flash A/B 验收

使用同一项目、同一模型与相邻两个五集批次进行比较：

| 指标 | 当前基线 | 优化通过线 |
| --- | --- | --- |
| 五集调用 | 50 | ≤21 |
| 输出 token | 54,461 | 较基线下降至少 40% |
| 缓存命中率 | 14.6% | ≥30% |
| 五集成功 | 5/5 | 5/5 |
| 单集字数 | 928–1,263 | 900–1,500 |
| 对白比例 | 47%–60% | 45%–75% |
| 每集建议 | 平均 9.2 条 | ≤5 条 |
| 明显人物/动作/道具错误 | 存在 | 人工抽查无明显错误 |

验收顺序：

1. 先在测试项目运行一批 5 集，不直接消耗正式 100 集项目后续剧情。
2. 通过调用预算与结构检查后，再运行《灰烬账本》第 11–15 集。
3. 人工重点抽查第 10→11 集承接、证据出现顺序、道具保管和人物对白。
4. 通过后连续运行至第 20 集；未通过则只修失败节点，不扩大架构范围。

## 7. 文档与契约同步

开始改代码前先同步以下冲突：

- `SHORT_DRAMA_MODE_SPEC.md` 当前仍写“字数 ±15% 为 blocking”，应改为目标 75%–125% 之外才产生 advisory，字数本身不阻止安全正文完成。
- `SHORT_DRAMA_RELIABILITY_PLAN.md` 第 15.3 节仍写“字数不足或超限属于 blocking”，应与当前实现和本计划统一。
- `SHORT_DRAMA_MODE_SPEC.md` 的正常路径 3 次/集继续保留，并补充异常路径单集硬上限 6 次。
- 校稿契约增加 `ScriptSanityReview` 的有限类别和最多问题数。
- 批次报告增加脱敏调用统计，但不得暴露 API Key、Prompt 或原始模型输出。

## 8. 实施顺序与提交边界

建议拆成五个可独立回滚的提交：

1. `docs: align short drama quality and call budgets`
2. `feat: expose short drama call metrics`
3. `perf: cap flash episode generation calls`
4. `feat: add focused script sanity review`
5. `feat: optionally continue fixed script batches`

优先级：P0 → P1 → P2 → P3 → P4 → P6 → P5。

P0–P4 完成并通过真实五集验收之前，不启动 100 集自动连续生成。

## 9. 明确不做

- 不引入 LangGraph、BAML Runtime、向量数据库或新的 Agent 框架。
- 不逐场调用模型。
- 不让 AI 为文学性意见反复重写整集。
- 不要求每集精确 1,200 字或精确 60% 对白。
- 不自动接受 AI 无法定位、无法确定的剧情判断。
- 不删除现有 checkpoint、continuity、CAS 和原子提交能力。
- 不为降低调用数而跳过人物 ID、结构、禁项和版本冲突检查。

## 10. 完成定义

本轮优化完成必须同时满足：

- 五集 Flash 真实调用不超过 21 次；
- 五集全部完成，任一单集没有空场、人物串线或结构污染；
- 单集 900–1,500 字、对白 45%–75% 作为可用范围；
- 每集默认最多展示 3 条、总计最多 5 条有效建议；
- 真实抽查不再出现“已经拿走又重新发现”等明显动作矛盾；
- 正式稿与 continuity 仍然原子提交，失败候选不覆盖正文；
- 100 集离线调度通过，线上至少稳定完成前 20 集；
- 后端、前端 typecheck、全量测试和构建全部通过；
- 文档、实现、UI 文案和验收标准一致。

## 11. 当前实施进度

2026-08-17 第一批已完成：

- 规格与可靠性文档统一为“字数、对白比例只提示，不单独阻断”。
- 安全短稿最多自然续写一次，单次建议续写上限由 450 调整为 700 字。
- AI 校稿收敛为 `ScriptSanityReview`，只保留人物在场、说话人、道具归属、知情时点、因果顺序、连续性矛盾和重复动作七类明显问题。
- 服务端对 AI 轻校结果去重并限制为每集最多 3 条，过滤文学性和风格噪声。
- 批次结果统计 primary、Fixup、fallback、节点与每集调用次数，并写入任务完成信息。
- 策划编辑页可直接选择并保存 20%—90% 的对白目标比例。
